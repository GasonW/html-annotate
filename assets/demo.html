1 为什么需要 HTML 批注？

2026 年 5 月，Anthropic 发布了一篇有影响力的文章：HTML is the new Markdown — AI 生成的内容应该用 HTML 直接呈现在浏览器里，而不是堆在 Markdown 里等着渲染。HTML 有排版、有色彩、有表格、有 callout——比 Markdown 更可读，更适合人机协作。

但这带来了一个关键缺口：

Markdown 的好处是"可评论"：任何人都可以在任意行下面写一条意见。
HTML 的问题：它好看、结构化，但没有原生的批注能力——你无法在某个标题、某段文字、某个表格单元格旁边写评论，Agent 也就无从知道"这里需要改什么"。

HTML Annotate 就是为填补这个缺口而生的。它不修改源 HTML，而是通过一个本地服务动态注入批注 UI，让你在任意 HTML 页面上做到：

🖊️
文字划线 · 荧光批注
选中任意文字，点击浮动按钮添加评论。弱态为荧光下划线，hover / 选中态切换为高亮背景。
🖼️
图片批注 · 截图即反馈
Cmd+V 直接粘贴剪贴板图片，或上传文件。图片与文字评论一起存储，适合截图标注、UI 对比。
🤖
AI 可直接消费
批注数据以 JSON 存储，图片自动提取为 PNG。Claude Code Skill 一键读取，Agent 理解意图后修改源文件。
📄
不侵入源文件
批注数据独立存放在 .annotations.json 中。源 HTML 完全不被修改，可随时开关批注模式。

4 技术设计

架构原则

零侵入。源 HTML 文件不做任何修改。Python HTTP Server 在 serve 时动态注入 <script> 标签，浏览器加载独立的批注 UI 脚本。批注数据存储在独立的 JSON 文件中，与源文件完全解耦。

高亮实现

使用 document.createTreeWalker() 遍历选区内的文本节点，每个文本节点单独包裹 <span class="ann-hl">，避免块级元素被内联标签包裹导致的布局破坏。

浮动按钮定位

使用 mouseup 事件的 clientX/Y 坐标直接定位，让按钮出现在鼠标松手的位置，而非选区矩形中心——减少鼠标移动距离。

数据流

// annotate.js → HTTP API → Python Server → .annotations.json
save() → POST /__ann__/api/data?file=xxx.html
load() → GET  /__ann__/api/data?file=xxx.html

// Claude reads annotations
$ python scripts/read-annotations.py xxx.annotations.json
→ 打印未解决批注摘要
→ 提取 base64 图片为 /tmp/ann_images/ann*.png

5 快速开始

前置依赖

$ pip install --upgrade pip  # 仅需标准库，无需额外依赖

安装为 Claude Code Skill

$ git clone https://github.com/GasonW/html-annotate.git ~/.claude/skills/annotate

使用

# 在 Claude Code 中
/annotate path/to/report.html

# 浏览器中批注完成后
"帮我根据批注修改"

# 或手动运行读取脚本
$ python scripts/read-annotations.py report.annotations.json
